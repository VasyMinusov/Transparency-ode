# Архитектура системы

## Общая схема

```
┌────────────────────────────────────────────────────────────────┐
│ Tauri-приложение (desktop)                                     │
│ ├─ Rust-shell: окно, команды backend_status / start_backend    │
│ └─ React + TypeScript (Vite, pnpm):                            │
│    Проверка сущностей · Сигналы · Контракты · НПА · Модели     │
│    Слой данных: src/data/ (TransparencySource + httpSource)    │
└───────────────┬────────────────────────────────────────────────┘
                │ REST /api/v1, OpenAPI 3.1 (Swagger на /docs)
┌───────────────▼────────────────────────────────────────────────┐
│ FastAPI (Python 3.14, uv)                                      │
│ ├─ api/v1: entities, report, verdict, expert, agent, legal,    │
│ │          decisions, graph, tenders                           │
│ ├─ services:                                                   │
│ │   expert.py    — низходящая экспертная система (R1–R10, C1–C3)│
│ │   agent.py     — восходящий агент (корреляции, LLM-озвучивание)│
│ │   legal.py     — поиск по корпусу НПА (TF-IDF, legal RAG)    │
│ │   predictor.py — XGBoost + SHAP (оценка риска)               │
│ │   graph_builder.py — NetworkX + кэш центральностей           │
│ │   statistics.py — статистические заборы Тьюки (методика OCP) │
│ │   explainer.py — гипотезы (GigaChat / Ollama / offline)      │
│ ├─ adapters/ — единый контракт источников (procurement, tenders)│
│ └─ SQLAlchemy 2.0 + SQLite (MVP) → PostgreSQL (смена URL)      │
└───────────────┬────────────────────────────────────────────────┘
                │
┌───────────────▼────────────────────────────────────────────────┐
│ Данные: SQLite (entities, relations, tenders, bids, decisions) │
│ Моки: data/mock_registries/*.json (seed=42, явные data_source) │
│ Корпус НПА: data/legal_corpus.json (конспекты статей)          │
└────────────────────────────────────────────────────────────────┘
```

## Гибридная модель анализа

- **Низходящая часть** (экспертная система): знания о схемах → правила → проверка фактов.
  Детерминирована: правило либо сработало, либо нет; цепочка «Факты → Признаки →
  НПА + методика → Вердикт» полностью объяснима.
- **Восходящая часть** (агент, подход Palantir): корреляции в данных, не зашитые в правила
  (кластеры адресов, пересечение сигналов, узлы-посредники). LLM только формулирует
  текст поверх структурированных находок; провайдер: offline (детерминированно) /
  GigaChat / Ollama (локально).
- **Предиктивный слой**: XGBoost + SHAP — оценка риска с объяснением вклада факторов.

## Кэши и детерминированность

- Версия данных (`services/datacache.py`) инвалидирует кэши графа, центральностей
  (betweenness считается один раз за версию), вердиктов и ленты сигналов.
- Решения сотрудника на данные не влияют — кэши не трогают.
- Обучение модели и генерация моков — с фиксированным seed=42.
- `POST /load` и seed поднимают версию данных; GZipMiddleware для ответов >1 КБ.

## Безопасность

- Персональные данные не обрабатываются.
- Синтетические данные явно помечены (`data_source` в каждой записи и сигнале).
- CORS ограничен: Tauri-окно и Vite-dev.
- LLM в локальном контуре (Ollama) — данные не покидают машину.
