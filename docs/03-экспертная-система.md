# Экспертная система

Низходящая модель: знания о коррупционных схемах → правила → проверка фактов по данным.
Каждый сигнал объясним: факты, описание срабатывания, НПА, методическое основание
(Минтруд / ГУСП / OCP), подобранные статьи (legal RAG) и «что запросить».

## Контрактные правила (по связям контрактов)

| Правило | Схема | Степень | Срабатывание |
|---|---|---|---|
| R1 | Единоличный поставщик | средняя | доля одного поставщика > 60% суммы, ≥3 контрактов |
| R2 | Аффилированность (общий адрес) | высокая | ≥2 контрагентов с одним адресом |
| R3 | Аномальная цена | средняя | средний чек — статистический выброс (забор Тьюки Q3+1.5·IQR, методика OCP) |
| R4 | Дробление закупок | средняя | ≥5 мелких контрактов с одним лицом, медиана ≤ 30% максимума |
| R5 | Взаимная зависимость «свой поставщик» | высокая | двусторонняя концентрация > 50% |
| R6 | Круговая схема (встречные контракты) | высокая | контракты в обе стороны с одним лицом |
| R7 | Ротация поставщиков | средняя | ≥3 поставщиков, у каждого 1–3 контракта, близкие средние (CV < 0.7) |
| R8 | Единичный крупный контракт новому контрагенту | средняя | единственный контракт > 3× среднего заказчика |
| R9 | Срочные закупки в конце года | средняя | ≥50% контрактов в IV квартале, ≥4 шт. |
| R10 | Признаки фирмы-однодневки | средняя | регистрация < 6 мес. до первого контракта или УК ≤ 10 тыс. (ЕГРЮЛ-признаки) |
| R11 | Нестандартное авансирование | средняя | аванс > 50% по ≥2 контрактам (норма ст. 34 44-ФЗ — до 30%); след отката через аванс |
| R12 | Злоупотребление закупками у единственного поставщика | средняя | ≥4 процедур «у единственного» и доля > 40% (ст. 93 44-ФЗ — исчерпывающий перечень) |
| R13 | Массовый руководитель у контрагентов | высокая | один директор в ≥3 организациях контура сделок |
| R14 | Общий бенефициар с контрагентом | высокая | совпадение founder_id у сущности и контрагента (конфликт интересов) |

## Процедурные правила сговора (по тендерам и заявкам, OCP/WB GRAS)

| Правило | Схема | Степень | Срабатывание |
|---|---|---|---|
| C1 | Единственный участник конкурса | средняя | конкурентная процедура с одной заявкой (OCP R018) |
| C2 | Идентичные/кратные цены заявок | средняя | цены совпадают ±0.5% или круглые кратные 1000 (OCP R023/R028) |
| C3 | Пара соучастников с постоянным победителем | высокая | ≥3 совместных процедур, один всегда выигрывает (OCP R053) |
| C4 | Отсечение конкурентов на процедуре | средняя | ≥3 заявок, допущена одна — победитель (ГУСП: отклонение заявок) |

## Итоговый вердикт
- high-сигнал → «Требует немедленной проверки»; любой сигнал → «Повышенное внимание»;
  нет сигналов → «В норме». К вердикту — рекомендация действий.

## Как добавить правило
1. Добавьте блок в `_analyze_rules` (`app/services/expert.py`), создайте `Signal(...)`.
2. Добавьте записи в `METHODOLOGY` и `SIGNAL_ACTIONS`, при необходимости — в `LAWS`.
3. Добавьте позитивный и негативный кейс в `tools/eval_rules.py`, прогоните `make eval`.

## Качество правил
`make eval` — precision/recall на размеченных синтетических кейсах,
результат в `data/eval_report.json` (метрики для паспорта проекта).
