# transparency-client

Десктоп-клиент (Tauri: Rust + React/TypeScript) аналитической системы «Код прозрачности».
Хакатон «Код прозрачности» 2026, направление 04.

## Запуск

Требования: Node.js + pnpm, Rust toolchain (rustup), uv (для backend).

```bash
# 1. Backend (из корня репозитория)
cd ../transparency-api
uv sync
uv run uvicorn app.main:app --port 8000

# 2. Клиент
pnpm install
pnpm tauri dev        # откроет окно приложения
```

## Разделы

- **Проверка сущностей** — поиск организации, отчётная страница и экспертный вердикт.
- **Сигналы** — лента выявленных признаков коррупционных схем с уведомлениями.
- **Контракты** — реестр контрактов со статусом проверки (по мере подключения реестров).
- **Нормативная база** — НПА, на которые ссылается экспертная система.

## Экспертная система (низходящая модель)

Вывод строится от знаний о схемах к фактам, каждый шаг объясним:
**Факты → Признаки схем → Правовые основания → Вердикт и рекомендация**.
Правила (R1–R5): единоличный поставщик, аффилированность по адресу, аномальная
цена, дробление закупок, взаимная зависимость «свой поставщик».
Сигнал — основание для проверки человеком, не обвинение.

Граф связей сознательно заменён отчётной страницей: при более чем ~10 узлах
граф нечитаем, отчёт остаётся читаемым на любом масштабе.

## Архитектура данных

```
src/data/
├── types.ts       доменные типы (Report, CounterpartyRow, Decision…)
├── sources.ts     контракт TransparencySource + реестр источников
└── httpSource.ts  реализация поверх FastAPI
```

Новый реестр подключается реализацией `TransparencySource` и добавлением
в `SOURCES` — UI не меняется. Бэкенд-адаптеры (app/adapters/) дублируют
эту абстракцию на стороне Python.
